# Mobile Implementation Plan - Opcode Mobile Extension

## Objective
Create a comprehensive, phase-by-phase implementation plan for extending Opcode to mobile platforms, optimized for 15-agent parallel execution with maximum concurrency.

## Context

### Reference Documents
- Research findings: @.prompts/001-mobile-architecture-research/mobile-architecture-research.md
- Existing adaptation plan: @claudedocs/claude-code-mobile-opcode-adaptation.md
- Feature mapping: @claudedocs/feature-mapping.md

### Replit Mobile UX Reference (From Screenshots)
**Main Navigation (3 tabs):**
1. **Apps** - Project list with preview cards
2. **Create** - AI-powered build interface with templates
3. **Account** - Profile, usage, settings

**Workspace Views:**
- Agent execution with task progress
- Live preview with browser controls
- Tools menu (comprehensive list)
- Publishing workflow
- File/code editor

### Project Goals
1. Extend existing Opcode desktop app to iOS/Android
2. Replit-inspired mobile UX with touch optimization
3. Maintain ~75% code reuse from existing codebase
4. Open source best practices for community growth
5. Maximum agent parallelization during implementation

## Requirements

### Plan Structure
The plan must:
1. Break work into parallelizable phases
2. Identify dependencies between tasks (sequential vs parallel)
3. Assign specific agent types to each task
4. Specify exact file paths and folder structure
5. Include research checkpoints for SOTA best practices
6. Define verification criteria for each phase

### Agent Types Available (15 agents)
- `researcher` - Deep research and information gathering
- `system-architect` - System design and architecture decisions
- `coder` - Implementation, feature coding
- `backend-dev` - Rust/Tauri backend development
- `mobile-dev` - React Native/mobile-specific development
- `frontend-architect` - UI component architecture
- `tester` - Test creation and quality assurance
- `reviewer` - Code review and quality checks
- `cicd-engineer` - CI/CD pipeline and automation
- `security-engineer` - Security review and hardening
- `performance-engineer` - Performance optimization
- `technical-writer` - Documentation and guides
- `devops-architect` - Infrastructure and deployment
- `refactoring-expert` - Code cleanup and optimization
- `planner` - Task orchestration and coordination

### Folder Structure Requirements
New files must follow this structure:
```
src/
├── components/
│   └── mobile/                    # NEW: Mobile-specific components
│       ├── navigation/            # Bottom nav, tab bar
│       ├── workspace/             # Swipeable panes, workspace views
│       ├── terminal/              # Touch-optimized terminal
│       ├── editor/                # Mobile code editor
│       └── common/                # Shared mobile utilities
├── hooks/
│   └── mobile/                    # NEW: Mobile-specific hooks
├── layouts/
│   ├── DesktopLayout.tsx          # Extract from App.tsx
│   └── MobileLayout.tsx           # NEW: Mobile layout wrapper
├── lib/
│   └── mobile/                    # NEW: Mobile utilities
│       ├── connection/            # SSH, Tailscale, Web API
│       ├── gestures/              # Touch gesture handlers
│       └── platform/              # Platform detection
└── screens/
    └── mobile/                    # NEW: Mobile screen components

src-tauri/
├── src/
│   └── commands/
│       └── mobile/                # NEW: Mobile-specific Rust commands
│           ├── ssh_bridge.rs
│           ├── tailscale.rs
│           └── connection.rs
└── gen/                           # Generated by Tauri mobile init
    ├── android/
    └── apple/
```
